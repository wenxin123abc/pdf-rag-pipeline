# 四层框架规格

PDF-RAG 的工程解法拆成四层，加一个收尾闭环。每层有明确的输入、输出和失败模式，缺一层就会在某一类问题上崩。

## 判定树：拿到 PDF 先问三个问题

```
有文本层吗？（每页可提取字符 > 50）
├─ 否 → 扫描件：走多模态解析，页级视觉描述作主索引
└─ 是 → 有多栏吗？（x 轴存在 >10% 页宽的纵向空白带，且两侧各有 ≥3 个块）
        ├─ 是 → 先切栏再排序，否则左右栏串行
        └─ 否 → 有表格/图表吗？
                ├─ 有 → 表格结构化 + 图表生成描述，与正文分离
                └─ 无 → 标准文本管线
```

三个问题的答案决定后续所有参数。**跳过判定直接抽文本，是这套方案最常见的失败起点。**

## L1 多模态解析与按页定位

**做什么**：判断 PDF 类型，选解析器，完成文字提取 + 表格结构还原 + 图片理解，并以"页"为单位建立第一层索引。

| 类型 | 解析器 | 关键动作 |
|---|---|---|
| 原生文本 | PyMuPDF / pdfplumber | 抽 text 与 blocks，**保留 bbox 和字号** |
| 扫描件 / 图文混排 | MinerU 等文档解析模型、或视觉大模型逐页转写 | 逐页出 Markdown + 版面结构 |
| 多栏 | 左边缘聚类 + 页级多数投票 | 支持 1-4 栏；复杂串栏再换 pdfplumber |

**按页定位**：每页保留一个 `page` chunk，作为读取和引用兜底。若下游接入向量库，可以再为页或 section 生成 embedding；本技能包本身不生成向量。

**失败模式**：把扫描页当空页跳过 → 整页内容永久丢失，检索时表现为"文档里明明有，就是查不到"。

## L2 结构还原

**做什么**：不要只抽一坨纯文本，必须保留页码、标题、层级、章节段落、表格、图片说明、脚注，甚至页眉页脚的识别结果（用于剔除）。

**判断标准**：抽完之后能不能回答——
- 这段在第几章、第几条、第几页？
- 这个数字来自哪张表、哪个指标、哪一年？

合同切片必须知道"第几章第几条"；财报切片必须知道"哪张表哪个指标"。答不出来，模型再自信也追溯不回来源。

**脚本实现要点**（`extract_structure.py`）：
- 段落重建：PDF 常把一段话拆成"每行一块"，或用独立文本框放编号（"3.1"）。不重建就会出现半句话。
- 字号不同的块不合并：字号变化即结构边界（标题/题注/脚注）。
- 表格区域内的文本块从正文剔除，否则同一份内容进两次索引。
- 图内文字单独标记，不参与标题判定。

## L3 语义切片与索引

**做什么**：页内再按语义切片，并给每个 chunk 补 metadata 与上下文说明。

切片规则：
- 标题下的段落归一组，按 `max_chars` 上限切，**在块边界切，不切断句子**
- 表格单独做结构化（markdown），不与正文混
- 图片和图表生成摘要，长表格按行列转成结构化文本

**两个方向的主次策略**（决定索引哪一层当主索引）：

| 文档形态 | 主索引 | 文字的角色 |
|---|---|---|
| 文字为主 + 少量概念图 | section/table/image chunk | 主体内容 |
| 概念图为主 + 少量文字 | 每页视觉描述 | 补充元数据 |

纯靠一种索引覆盖所有文档形态，必然有一类文档效果很差。

## L4 Agent 工具链按需调用

**做什么**：Agent 不一次性把整本 PDF 灌进上下文，而是把 PDF 能力封装成一组工具。

| 工具 | 职责 |
|---|---|
| `search_pdf` | 检索相关片段，返回页码 + chunk_id |
| `read_page` | 读指定页全文 |
| `extract_table` | 抽指定表格的结构化内容 |
| `analyze_chart` | 看图，产出图表结论 |
| `quote_source` | 返回带页码的原文引用 |

**核心原则：按需加载，永不整本塞入。** 上下文窗口是稀缺资源，塞满整本 PDF 等于让模型在噪音里捞针。

## 收尾：可追溯 + 评测闭环

- **防幻觉**：回答必须带页码/章节/原文片段作为引用，前端支持点击跳转溯源。
- **评测不能只看答案对不对**，还要看：检索片段是否命中、页码是否正确、表格数值是否一致、图表结论是否真实。
- **离线预计算兜底**：像"出现违约条款最多的 3 种情况"这种聚合统计问题，纯向量检索逐条召回根本答不了，必须提前离线算好结构化统计结果存进知识库直接命中，不依赖模型现场推理。

本技能提供可追溯引用、批量语料、结构诊断、离线预览和真实检索评测；生产系统仍需按业务补充 OCR/复杂版面模型、权限、版本管理和发布治理。

## 面试表述（可直接复述）

> 不是 PDF 转文本再向量化，而是：先识别 PDF 类型 → 多模态解析并按页定位 → 还原文档结构 → 按语义切片并区分图文主次策略 → 通过 Agent 工具链按需检索、读页、抽表、看图 → 全程保留页码，做到引用可追溯、评测可验证、离线预计算兜底。

反面表述（会被判定为"只跑过 demo"）：

> "把 PDF 转成文本，然后切片入库。" —— 太浅，没有类型判定、没有结构、没有追溯、没有评测。
